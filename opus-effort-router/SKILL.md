# opus-effort-router

메인 세션은 Opus로 유지하고, 작업 난이도에 맞는 effort만 고른다.
모델 전환은 캐시를 깨지만, Opus 5.5에서는 effort를 바꿔도 캐시가 유지된다(공식 prompt-caching 문서 기준).

## 1. 난이도 판정

작업 전에 아래 표로 effort를 정하고, 응답 첫 줄에 `effort: <level> — <이유 한 구절>`로 알린다.

| effort | 이런 요청 |
|---|---|
| low | 파일 찾기, 이름 변경, 포맷 정리, git 조작, 짧은 사실 답변, 오타 수정 |
| medium | 범위가 분명한 단일 파일 수정, 간단한 기능 추가, 문서 요약 |
| high | 여러 파일 수정, 재현 가능한 버그 디버깅, 테스트 설계, 긴 문서 검토 |
| xhigh | 원인이 불분명한 버그, 설계 결정, 성능·동시성 문제, 법률·수치 검증 |
| max | 아키텍처 재설계, 보안 검토, 대규모 리팩토링, 틀리면 되돌리기 어려운 판단 |

- 확신이 없으면 한 단계 높게 잡는다.
- 되돌리기 어려운 작업(데이터 삭제, 배포, 법적 문서)은 최소 xhigh.
- 같은 대화에서 판정이 바뀌지 않으면 다시 알리지 않는다.

## 2. 실행 방식

1. low~high: 메인 세션에서 그대로 처리한다.
2. xhigh·max이고 핵심 추론이 필요한 작업: `opus-deep`에 맡긴다. 서브에이전트는 대화 기록을 못 보므로 목표·제약·관련 파일 경로·확인된 사실을 프롬프트에 빠짐없이 적는다. 결과는 메인에서 검증한 뒤 보고한다.
3. 판단이 거의 없는 반복·대량 작업: `opus-quick`에 맡긴다.
4. 세션 전체를 그 수준으로 진행해야 하면 `/effort <level>` 입력을 한 줄로 안내한다. Claude가 직접 실행할 수는 없다.

서브에이전트는 별도 컨텍스트에서 돌고 결과만 메인 대화 끝에 붙으므로 메인 캐시는 유지된다.

## 3. 서브에이전트 준비 (PC당 1회)

`~/.claude/agents/opus-deep.md`, `~/.claude/agents/opus-quick.md`가 없으면 사용자에게 묻고
`~/.claude/skills/_tools/agents/`의 같은 이름 파일을 복사한다. 복사 후에는 새 세션에서 인식된다고 알린다.

## 하지 말 것

- `/model` 전환을 권하지 않는다(캐시가 깨진다).
- 쉬운 요청을 서브에이전트로 넘기지 않는다. 컨텍스트를 옮기는 비용이 더 크다.
- 판정 설명을 길게 쓰지 않는다. 한 줄이면 된다.
