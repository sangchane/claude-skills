# SPEC 템플릿

## M — 1쪽 SPEC

```markdown
# SPEC: {{기능 이름}}
## 목표 — 누구의 어떤 문제를, 무엇이 되면 성공인가 (1~3줄)
## 안 할 것 — 이번 범위 밖 (목록)
## 완료 기준 — pass/fail로 판정 가능하게. 순서대로 구현한다
- [ ] {{기준 1}} — 검증: `{{명령 또는 확인 방법}}`
- [ ] {{기준 2}} — 검증: `{{…}}`
## 참고 — 따를 기존 패턴(file:line), 프로토타입에서 확인한 것
```

게이트: 완료 기준마다 검증 방법이 있다. "직관적인·빠른" 같은 표현은 측정 기준으로 바꾼다.

## L — 전체 SPEC

설계 패키지(dev:design 03·05·08)가 있으면 입력으로 쓴다. 설계 결정을 구현자에게 남기지 않는다.

```markdown
# SPEC: {{기능 이름}}
## 배경 — 왜 지금 필요한가
## 현재 상태 — 관련 코드 file:line
## 제안 변경 — 파일·인터페이스·데이터 흐름을 이름까지
## 완료 기준 — pass/fail 판정 가능, 요구사항 ID(FR-·SC-)와 연결
## 테스트 계획 — 단위/통합/E2E, 리스크 기반
## 검증 방법 — 끝나면 무엇을 실행해 "됐다"를 확인하나
## 롤백 계획
## 안 할 것
## 참조 파일
```

게이트: 낯선 구현자가 이 문서만으로 구현할 수 있고, 미결정 사항이 없다.
