# PC 게임 → 모바일 이식 노하우 (원작이 동작 명세인 프로젝트)

> 이식·리메이크(원작 게임·레거시 시스템을 새로 만드는 일)를 시작하거나 막혔을 때 읽는다. dev:design 규칙 13(볼트 PRD·스코프 노트·의도적 변경)이 문서 쪽, 이 파일은 **순서·검증·구현·운영 쪽**이다.
> 출처: 어둠의 전설 → 모바일(LOD, 2026-09~10, 6주) + 메이플스토리 1.23 → 모바일(2026-10-16~21, SPEC 30개). 날짜·사건 원문은 `evidence.md` 「2026-10-21 게임 이식」.
> 원칙 하나: **원작 코드·서버는 동작 명세로만 쓰고, 구현은 현대식으로 새로 설계한다.** 구조를 그대로 옮기면 원작의 구멍(평문 비밀번호·검증 없는 좌표·트랜잭션 없음)까지 옮긴다.

## 1. 순서 — 이 순서가 두 번 통했다

| 단계 | 하는 일 | 끝났다는 증거 |
|---|---|---|
| 0 준비 | 루트 저장소 + 원작 서버·참고 저장소는 **submodule**(원본은 안 고침, 고치면 fork). 압축은 각각 빈 새 폴더에 풀고 목록화. 실행 파일은 **복사본**을 분석 | 분석서 01(파일 목록·해시) |
| 1 분석서 | 구조 → 진입점·빌드 → **로그인→게임 흐름** → 자료 위치 → **프로토콜** → 외부 의존 → 모바일 전환 평가 → 빈 곳. 소스가 있으면 일반 도구, 없는 실행 파일만 REA(`reverse-engineering.md`) | 원작 서버를 실제로 띄우고 **자작 스크립트로 로그인 한 번**(포트 열림만 믿지 않는다) |
| 2 지식 볼트 | 아이템·몹·맵·NPC·분석서 절·코드를 한 그래프로, `ask <이름>` 한 줄로 찾기(knowledge-vault 스킬) | 같은 것을 두 번 찾지 않음 |
| 3 기획 | goals.md(완료 기준마다 잴 수단) · PRD 스코프 노트 · 의도적 변경(B 원작 버그 안 옮김 / C 모바일 때문에 바꿈) | design GATE |
| 4 **엔진 가설 실측** | 버리는 측정 장면 하나로 실기기 지연·fps·발열(30분)·소리 지연을 잰다 — 엔진을 고르기 전에 | 숫자(예: 아이폰 지연 p95 51ms, 30분 60fps) |
| 5 **정답 층** | 원작 규칙(물리·피해·공격 속도·성장)을 **참조 구현 + 시험 벡터**로 먼저 만든다(2절) | 벡터 = 참조 구현 |
| 6 한 바퀴 뼈대 | 로그인 → 캐릭터 → 맵 입장 → 이동(서버 재계산) → 저장·재접속 | 봇 시험 + 화면 끝까지 시험 |
| 7 콘텐츠 SPEC | 사냥 → 1차 직업 → 함께(같은 맵·대화·파티·교환) → 운영 → 2차 직업…, **플레이를 막는 것부터**, 꾸밈은 뒤 | SPEC마다 정답지·봇·화면 시험·그림 한 장 |
| 8 운영 | 개발·시험은 맥(격리 DB), 플레이는 클라우드. 배포는 남은 묶음 끝에 한 번 | `ops status` 종합 정상 |

- **웹 가능성을 엔진보다 먼저 정한다.** LOD는 Godot+C#로 만들었다가 웹 내보내기가 안 돼 막혔다. 메이플은 TS + Phaser + Capacitor(웹·iOS 한 코드), 서버도 TS — core 규칙을 서버·클라이언트가 **같은 파일**로 쓴다(3절의 전제).
- 원작 프로토콜이 TCP면 브라우저가 못 붙는다 → WebSocket 서버를 새로 짠다(원작 패킷 호환은 목표가 아니다 — 원작 클라이언트로 붙는 건 분석 단계 확인용).

## 2. 정답지 — 「원작과 같다」를 숫자로

- **정답 층과 제품 층을 다른 손이 쓴다.** 역공학 결과로 서브에이전트가 `scripts/re/ref_*.py`(참조 구현)와 벡터를 만들고, 메인이 `core/*.ts`를 쓴다 → 벡터 대조. 같은 손이 쓰면 오해를 같이 품는다(메이플: 물리 5/5·피해 18/18·공격 27/27이 첫 시도에 맞고, 리뷰가 29장면·350건을 따로 대조).
- **원작 실행물을 직접 돌려 벡터를 낸다** — 서버 jar를 반사로 불러 경험치 표·레벨업·세금 157건, 원작 로그인 서버에 시험 계정을 넣고 이름 규칙 64건. 「소스를 읽고 옮김」보다 강하다.
- 자료 정답지는 **원작 서버 XML·DB 덤프와 생성 결과를 전수 대조**(스킬 레벨 칸 6196/6196, 상점가 224/224, 장비 조건 589/589). 맞은 수/전체로 보고한다.
- 원작에 **없는** 수치는 지어내지 않는다: 근거 순서 = 원작 클라이언트 자료 → 클라이언트 코드(역공학) → 원작 공식 공지·퀴즈(메이플 구슬 30개는 넥슨 3차 전직 퀴즈 문항으로 확인) → 에뮬레이터 → 스킬 설명 글. 끝까지 없으면 「미확인」 + 설계값 + `shortcut:` 주석.
- **에뮬레이터는 명세지 정답이 아니다.** 「아직 코딩하지 않음」 대본, 후대 판 대본(그 판에 없는 아이템), 뒤집혀 보이는 조건(보스에게만 걸리는 MP 흡수)이 섞여 있다 — 클라이언트 코드·자료로 교차 확인하고, 다르면 둘 다 적는다.
- 미확인 갈래는 기존 동작 유지 + 예외를 던지게 둔다(옮기지 않은 무기 계열 → 피해 계산 예외). 조용히 0을 내면 나중에 못 찾는다.

## 3. 서버 권위 + 클라이언트 예측 (손맛과 치트 방지를 같이)

- 이동: 클라이언트가 입력 묶음(3틱)을 보내고 **서버가 같은 물리로 다시 돌려** 어긋나면 보정(`refSeq` 뒤 묶음 다시 돌리기). 서버만의 자료(맵 경계 벽처럼 로딩 때 덧붙이는 것)를 클라이언트가 안 쓰면 맵 끝에서 끝없이 되돌려진다 — **봇은 서버 물리를 써서 못 잡고 사람 손(눈가린 점검)이 잡았다.**
- 피해: 원작처럼 같은 씨앗 난수기로 클라이언트가 예측 피해를 바로 보이고 서버가 다시 계산한다. 규칙: ① 입력 조립 함수 하나(`physicalInput`)를 둘이 같이 ② **거절돼도 대상마다 난수를 같은 개수 소비** ③ `damage-mismatch` 로그 0을 시험 기준으로 ④ 확률 효과 중 클라이언트에 없는 것(독·빙결·훔치기·파이널 어택 굴림)은 서버 난수로 — 원작이 클라이언트에서 굴렸어도 서버가 굴리면 조작할 수 없다.
- **「몹이 되살아난다」 류는 시각 경쟁이다** — 메이플에서 원인이 셋이었다: 막타 앞 타격의 답(HP 남음)이 막타 예측을 덮음(답마다 순번 `refSeq`), 날아가는 탄의 서버 HP가 꽂히기 전에 들어와 두 번 뺌(꽂힌 뒤 반영), 서버가 몹의 지금 자리만 봐서 클라이언트가 늦게 본 자리의 막타를 놓침(직전 몇 틱 자리 `trail`도 판정). 기록(`attack-miss`·`hit-taken`·화면 진단)을 먼저 배포해 원인을 잡고 고쳤다 — 짐작으로 세 번 고치지 않는다.
- 공격 간격 검사는 「도착 시각」이 아니라 **동작 시작 시각**(도착 − 판정 시점) + 망 몰림 여유로. 도착 기준이면 동작마다 판정 시점이 달라 정상 공격을 거절한다.
- 다른 사람에게는 **서버가 다시 돌린 값만** 보낸다(이동 틱 자리·확정 피해). 막타 숫자는 피해를 매기기 전에 보내야 구경꾼에게 보인다.

## 4. 시험 체계 — 층마다 다른 것을 잡는다

| 층 | 무엇 | 잡는 것 |
|---|---|---|
| core 단위 + 벡터 | 순수 규칙, 몇 초 | 식·경계 |
| 서버 봇 시험 | 진짜 서버 + 격리 DB, **시계 주입**(시험이 시계를 당기고 정리·몹 틱을 직접 부름) | 판정·저장·동시성 |
| 헤드리스 화면 시험 | Playwright로 실제 클라이언트, 기능마다 `scripts/play/<기능>.mjs`, 그림 `out/play/*.png` | 화면 연결·예측-서버 어긋남 |
| 긴 봇 | 새 캐릭터 레벨 1 → 10 → 전직 → 재접속을 서버 같은 프로세스에서 | 한 바퀴가 실제로 도는가, 원작 물리 구멍(벽 뚫림·맵 밖 추락을 봇이 찾았다) |
| 눈가린 점검 | 코드 안 준 새 에이전트가 goals.md와 앱만 보고 | 입구를 못 찾음, 화면 가림 |
| 실기기 측정 | 지연·fps·발열 30분 — 「시작」과 「결과 받기」 스크립트를 나눠 백그라운드로 | 폰에서만 나는 것 |

흔들리는 시험의 원인은 거의 시험 쪽이었다 — 먼저 의심할 것:
- **동시 실행 부하**: 화면 시험을 다른 시험·역공학·긴 봇과 같이 돌리면 겨누기·보정 단계가 흔들린다. 다 쓴 브라우저 창을 닫지 않아 게임 7개가 동시에 돈 적도 있다(한 판 28분). 화면 시험은 **단독으로**.
- 판정을 값 읽기가 아니라 **서버 메시지로**: HP를 읽기 전에 자연 회복이 끼어 「맞기」가 실패 → 맞음 메시지로 판정.
- 무작위 리젠·몹 이동: 시험마다 전용 사냥터, 미리 돌려 보고 설 자리 고르기, 몹을 지나가지 않는 쪽으로 접근.
- 원작 규칙이 시험을 막음: 시험 캐릭터 이름이 원작 금지어(「파티」·「운영」·「제작」), 레벨 1은 사냥터에서 죽음 → 이름·능력치를 시험이 정한다.
- 화면 시험 조작: 키보드가 안 붙은 터치 게임이면 조이스틱을 마우스로 누른 채, 계정을 바꾸려면 초대 코드를 하나 더(세션은 하던 캐릭터로 이어진다).
- 「통과로 셌는데 사실 빈 곳을 쐈다」 — 맞힌 결과만 센다. 고친 버그는 **고치기 전 실패하는 시험**을 먼저 확인.
- 시험 DB는 끝나면 지운다(안 지워 40분에 681개·5.6GB가 쌓였다). 「DB 지우지 마」 같은 금지 문구는 **대상을 이름으로**(「개발 DB」) — 서브에이전트가 시험 DB까지로 읽었다.
- 확률이 걸린 시험은 기회를 여러 번 주고(약한 무기로 몹이 오래 버티게), 실제로 그 갈래를 탔는지 한 번은 찍어 본다.

## 5. 모바일 화면·조작

- **가로 고정**(세로로 열면 화면을 돌리고 터치 좌표도 돌림), 사파리 안전 영역·상단바(웹앱 meta·`black-translucent`), 창 높이 기준 **390pt**(폰 가로) — 긴 메뉴·카드는 그 높이에서 잘리는지 그림으로 본다.
- 조작판: 왼손 이동(누른 손가락만 이동, NPC를 누른 손가락은 빼기) · 오른손 공격 둘레 부채꼴(점프·스킬·콤보·물약), **두 손가락 동시 입력**(방향+공격, 위+점프로 밧줄)을 처음부터 시험. 방향 처리는 공격보다 먼저(공격을 누른 채 몸을 못 돌렸다).
- 원작 키보드 조작을 터치로 옮기며 생긴 편의는 의도적 변경 C로 적는다: 지나가면 줍기(원작 Z), 콤보 세트(메이플M 스킬 프리셋 4×6), 자동 물약(메이플M 펫·리니지M 빠른 칸 조사), 추천 빌드, 지도로 이동. **경쟁 모바일 게임이 같은 문제를 어떻게 풀었는지 조사해 제안**한다 — 사용자가 고른다.
- 원작 그림·아이콘을 그대로 쓰고, 메뉴 아이콘이 원작에 없으면 원작 아이템 그림에서 고른다(「진짜 가방 모양」을 위해 아이템 1,000여 개를 훑었다). 지어낸 그림보다 원작 그림.
- 그림 묶음: 맵 묶음별 아틀라스 장을 따로 받고 맵을 옮기면 앞 장을 내린다(전부 올리면 폰 GPU 메모리 약 200MB). **장을 못 받으면 Phaser가 초록 격자를 그린다** — 빠진 장은 안내 뒤 다시 받기.
- 사용자 사진에서 원인을 찾는다: 격자 크기·자리를 맵 경계와 맞대 원인을 찾고, 헤드리스로 재현한 뒤 고쳤다.

## 6. 운영 — 혼자 돌리는 작은 서버

- 처음부터: 운영자 명령(지급·이동·잠금·공지)·한 줄 JSON 로그(날짜별 파일)·`/healthz`·암호화 매일 백업 + **복원 연습**·`ops.sh up|status|backup|restore-drill`.
- 상태 확인은 **본문까지**(`{"ok":true}`) — 「200이면 정상」이 같은 맥의 다른 프로젝트 서비스를 정상으로 봤다. 운영 포트는 개발·시험과 겹치지 않게.
- 배포하면 접속자가 끊긴다 → 직전에 알린다. 사람이 사냥 중이면 미룬다. 캐릭터 DB를 손으로 고칠 때는 **서버를 멈춘 사이에**(메모리가 덮어쓴다).
- 사용자가 「버그」를 말하면 먼저 **운영 기록**을 읽는다(그 시각 그 캐릭터의 거절·처리 줄) → 로컬 재현 스크립트 → 고침. 「표창이 안 낀다」는 수량 1짜리 세 묶음이었다.
- 클라우드 무료 티어(오라클)는 자리가 없을 때가 많다 — 자리 잡기는 launchd로 상시 재시도, 그동안 작은 판으로 연다.

## 7. 시행착오 표 (같은 실수 막기)

| 사고 | 원인 | 막는 법 |
|---|---|---|
| 교환하면 아이템이 복제될 수 있음 | 메모리를 바꾸는 시점이 저장 사슬보다 앞서 단독 저장이 교환 뒤 상태를 혼자 확정 | 둘을 바꾸는 일은 저장 사슬 안에서(`saveTogether(a, b, apply)`), 장애 주입(DB 트리거)으로 시험 |
| 버린 아이템 복제 | 버린 쪽 저장 전에 남이 줍고 서버가 죽음 | 저장이 끝난 뒤 바닥에 |
| 값 0 품목을 사서 되팔면 돈 무한 | 원작 값 0 품목 | 원작처럼 값 0 이하 거절, 리뷰가 찾음 |
| 맵 끝·벽에서 맵 아래로 끝없이 추락 | 원작 물리에 공중 벽 충돌·맵 경계 처리가 있는데 안 옮김 | 긴 봇이 찾음 → 역공학으로 원작 규칙 옮김(봇 우회 금지) |
| 사용자 요청을 두 번 잘못 읽음(파티 경험치) | 「130%를 모두가」를 「130%를 나눔」으로 | 규칙 요청은 **숫자 예**(둘이 잡으면 한 마리에 각자 몇)로 되물어 확인 |
| 「자료에 없다」고 적었는데 있었음 | 다른 폴더를 안 봄 | 「없다」 전에 전체 색인 검색, 여러 저장소 한 번에 |
| 서브에이전트 역공학 보고가 틀림(「정확히 1마리」) | 분기 해석 실수 | 핵심 분기는 메인이 디스어셈블로 다시 읽는다 |
| 분석서 절 번호가 겹침 | 새 번호를 확인 없이 씀 | 번호를 쓰기 전에 문서 목차 grep |
| 도커 앱을 켜니 남의 컨테이너도 켜짐 | 재시작 정책 | 켜기 전에 사용자에게, 켜진 것 목록 보고 |
| 서버 타이머 예외로 서버가 죽음 | 몹 틱 예외 처리기 없음, 공중 소환이 없는 발판을 참조 | 틱 경로는 예외를 기록만 하고 계속, 입력(소환 자리)은 발판 위만 |
| 원작 자료 이상값(음수 프레임 시간) | 자료 그대로 합산 | 생성기에서 크기만 쓰고 [추정] 주석 |

## 8. 사용자와 일하기 (이식 프로젝트에서 확인된 선호)

- 단계마다 **화면 그림 한 장**으로 보고. 보이는 브라우저 창 금지(헤드리스).
- 원작대로냐, 모바일에 맞게냐가 갈리면 **원작이 어떻게 했는지 조사해 보여 주고 선택지 두셋**을 낸다(「원작은 장비 창에 끌어 놓기만 — 모바일은 착용 칸 → 강화 → 주문서」). 사용자가 「모바일에 맞게」를 고르면 의도적 변경 C로 남긴다.
- 사용자 지적은 메모리에만 두지 말고 프로젝트 AGENTS.md 규약·스코프 노트로(dev rules.md).
- 원작 이식은 권리 문제가 있다 — 비공개(초대·가까운 지인)로 운영하고 공개·상용화는 따로 정한다.
