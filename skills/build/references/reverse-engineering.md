# 남의 앱·웹 동작 파악 (역공학) — EXPLORE 보조

> 연동·재현하려는 기능이 **남의 앱·웹사이트 안**에 있을 때 읽는다(예: 부동산 포털 매물 페이지에서 매물 ID·가격·등록일이 어디서 오나).
> 도구: [morluto/rea](https://github.com/morluto/rea) — "Reverse Engineer Anything" MCP(MIT, ★20.8만, 2026-10-14 확인). 웹사이트(페이지 구조·스크립트·네트워크 관찰), 저장한 HAR, Android APK·기기, JS/Electron, .NET, 네이티브 바이너리를 **증거와 한계를 붙여** 돌려준다.
> 실행 파일(exe·dll) 풀이는 3-1절(디스어셈블러 둘 이상), 브라우저를 직접 눌러야 하면 3-2절(Aside 기본, 사이트가 안 받으면 헤드리스).
> 순서: **관문 → 가장 덜 침습적인 방법 → 필요할 때만 REA**. 관문을 건너뛰면 기능을 다 만든 뒤 법·차단 때문에 버리게 된다.

## 1. 관문 (코드 전에, SPEC "안 할 것·제약"에 기록)

대상마다 아래를 확인하고 출처 URL·확인일을 남긴다.

| 확인 | 어떻게 |
|---|---|
| robots.txt | `curl -s -A "Mozilla/5.0" https://<호스트>/robots.txt` — 호스트마다 다르다(같은 회사도 서브도메인별로 다름) |
| 이용약관의 자동 수집·복제 조항 | 서비스 약관 원문. 못 찾으면 "미확인"으로 두고 허용으로 치지 않는다 |
| 봇 차단 | 평범한 요청에 403·캡차·CloudFront/Akamai 차단 페이지가 오면 **차단된 것** |
| 로그인·유료 필요 여부, 개인정보(중개사 연락처 등) 포함 여부 | 페이지를 사람이 열어 본다 |

판정:
- **허용**(robots 허용 + 약관에 금지 없음): 공개 페이지를 낮은 빈도로, 사용자가 고른 건만 읽는다.
- **애매**(약관 미확인·robots 일부 금지): **사용자 주도 방식만** — 아래 2절 ①②.
- **금지·차단**(robots 전면 금지, 약관 금지, 봇 차단): 자동 수집하지 않는다. 사용자가 화면에서 본 값을 입력·교차검증용으로만 쓴다.

어떤 경우에도 하지 않는다: 봇 차단·캡차·로그인·DRM·접근 통제 우회, 대량·체계적 수집(저작권법 DB 제작자 권리, 정보통신망법·업무방해 위험), 비공개 API를 반복 호출해 그 서비스를 대신하는 것. REA 자체 고지(DISCLAIMER.md)도 같은 선을 긋는다.

## 2. 덜 침습적인 방법부터

① **공유 URL 파싱** — 사용자가 앱·웹의 공유 버튼으로 받은 URL에서 사이트·매물 ID를 뽑는다. 네트워크 요청 0회. 출처 기록·중복 판별은 이것만으로 된다.
② **사용자가 연 페이지 읽기** — 북마클릿·브라우저 확장이 **사용자 브라우저에서 사용자가 지금 보고 있는 페이지 1건**의 DOM(또는 페이지에 이미 실린 JSON)을 읽어 우리 앱에 보낸다. 사람이 연 화면을 옮겨 적는 것과 같은 범위. (예: bergside/design-md-chrome이 같은 방식으로 스타일을 읽는다.)
③ **공식 API·제휴·공개 데이터**가 있으면 그것이 우선이다(국토부 실거래처럼).
④ 위로 안 될 때만 REA로 구조를 파악한다(3절). 파악 결과로 ①②의 파서를 만드는 데 쓰고, 자동 반복 수집으로 바로 가지 않는다.

## 3. REA로 파악하기

- 설치는 사용자가 직접(대화형 승인): `! npx rea-agents setup` → 에이전트 재시작. Node 22.19+ 필요. 설치돼 있지 않으면 브라우저 도구(개발자 도구 네트워크 탭)로 같은 관찰을 한다.
- 웹: 사용자가 **자기 브라우저에서 평소처럼 연 페이지**를 브라우저 분석하거나, 사용자가 저장한 HAR을 넘겨받는다. HAR은 쿠키·인증 헤더를 지운 뒤 받는다(`docs/web-network-captures.md`).
- 앱: APK 정적 분석(JADX)은 "어떤 화면이 어떤 데이터를 쓰나"를 아는 데까지만. 인증서 고정 해제·트래픽 가로채기는 1절 금지 항목에 걸리면 하지 않는다.
- 결과는 REA 형식 그대로 **증거·한계**를 붙여 SPEC에 남긴다: 필드 대응표(사이트 필드 → 우리 필드), 식별자(매물 ID·URL 패턴), 변경·삭제를 알 수 있는 신호, 그 신호가 틀릴 수 있는 경우.

## 3-1. 실행 파일(exe·dll) — 한 분석기를 「전부」로 믿지 않는다

rea 의 Ghidra 경로만으로는 빈 곳이 생긴다. 2026-10-16 원작 게임 클라이언트(32비트 윈도우 exe) 시험에서 확인한 것:
- **함수 목록표(vtable)로만 불리는 함수를 Ghidra 가 함수로 못 잡는다** → 되살린 코드·어셈블리 둘 다 없음. 창별 패킷 처리가 통째로 빠졌다.
- `procedure_callers` 가 "complete" 라고 표시하면서 **부르는 쪽이 함수 밖이면 조용히 뺀다**(실제 113곳 중 56곳 누락, 경고 없음 — 처음엔 생성자 58개 중 1개만 빠진 줄 알았다).
- rea 의 `inspect_with_objdump disassemble` 는 응답 한도를 넘고, 증거 묶음으로 꺼내도 16MiB 에서 잘린다(주소 범위 옵션 없음).

같은 복사본을 세 분석기로 비교(2026-10-17, 정답은 objdump 로 센 값): 기반 생성자를 부르는 곳 113곳 중 **Ghidra 57 · IDA Free 113 · Hopper 113**. Ghidra 가 함수로 못 잡은 지도 창 함수도 IDA·Hopper 는 잡았다. 되살린 코드는 IDA 가 읽기 쉽고(351줄), Hopper 는 레지스터를 그대로 옮겨 길다(1,313줄). 함수 시작은 IDA 가 맞았고 Hopper 는 앞 채움 2바이트(`mov esi,esi`)를 넣었다.

그래서 판마다:
1. **rea + Ghidra**(`GHIDRA_INSTALL_DIR`) — 함수·호출 관계·글자·표로 기능별 진입점을 잡는다. 창 없이 돈다.
2. **rea + IDA Free**(`--provider ida`, 설치돼 있으면) — 1의 목록을 맞춰 보고 빈 곳을 메운다. 목록표로만 불리는 함수까지 잡는다.
3. **로컬 `objdump -d` 전체 풀이 + 스크립트** — 「몇 곳인가」 같은 수 세기의 정답. 수 초면 끝난다.
4. 셋째 의견이 필요하면 **rea + Hopper 데모**(`--provider hopper`).
5. 서로 다르면 **기계어가 정답**이다. 어느 분석기의 어떤 목록이 틀렸는지 결과 문서에 적는다.

IDA Free 설치·연결(macOS):
- 받는 것은 사용자(Hex-Rays 계정) — 설치 zip 과 라이선스 `idafree_<번호>.hexlic`. zip 은 서명(Hex-Rays SA)을 확인하고 `…/Contents/MacOS/osx-arm64 --mode unattended` 로 창 없이 설치된다. 라이선스 파일은 **`~/.idapro/`** 에 둔다(모든 프로젝트가 같이 쓴다). 첫 실행의 약관 동의는 사용자.
- 연결 플러그인 [0xshlomil/ida-free-mcp](https://github.com/0xshlomil/ida-free-mcp) 은 **완성본이 `0.0.0.0` 에 인증 없이 열린다**(같은 와이파이 누구나 접속) → 소스 1.1.3 이상에서 `HOST` 를 `127.0.0.1` 로 고쳐 빌드(`cmake`)해 `~/.idapro/plugins/` 에 넣는다.
- 무료판은 자동 실행(`-A`)·명령줄 스크립트(`-S`)를 막는다. 플러그인 `init()` 에 `if (getenv("IDA_MCP_AUTOSTART")) mod->run(0);` 을 더해 빌드하면, `IDA_MCP_AUTOSTART=1 "<IDA>.app/Contents/MacOS/ida" <대상>` 으로 창을 열고 「Load a new file」 OK(Enter) 하나로 연결이 열린다. 로그의 「The initial autoanalysis has been finished」를 기다린 뒤 묻는다.
- rea 등록: `{"mode":"attached","protocol":"native","url":"http://127.0.0.1:13337/mcp"}` 파일을 `REA_IDA_MCP_CONFIG` 로(rea MCP 서버 env 에도 넣는다). IDA 창은 rea 가 물을 때마다 화면이 옮겨 다닌다.

Hopper 데모: 기한 없이 쓸 수 있다(제한은 30분마다 꺼짐 · 저장·내보내기 안 됨 · 디버거 없음). `brew install --cask hopper-disassembler` 뒤 `HOPPER_LAUNCHER_PATH="/Applications/Hopper Disassembler.app/Contents/MacOS/hopper"` — rea 가 물을 때마다 Hopper 를 열어 처음부터 분석한다. 첫 실행에서 데모 선택은 사용자. 한 번에 몰아 묻고 끝나면 닫는다.
결과는 기능마다 **어느 도구로 확인했는지**(rea 함수 · objdump 스캔 · IDA) 근거 칸을 붙인다. 사용자가 "어떤 도구를 썼나"를 물으면 그 칸으로 답한다.

## 3-2. 브라우저 직접 조작 — 보이는 브라우저(Aside) 기본

페이지를 보고 눌러야 하는 일은 **보이는 브라우저(Aside)가 기본**이다 — 사용자가 로그인해 둔 브라우저라 사람이 하는 것과 같은 화면이 나오고, 사용자가 옆에서 볼 수 있다. 사용자가 **이미 연 페이지**, 여러 화면을 눌러 지나가야 드러나는 동작, 스크린샷과 DOM 을 함께 봐야 할 때 특히.
- **헤드리스(Playwright)로 바꾸는 때**: 그 사이트가 Aside 의 조작을 받지 않을 때(Aside 가 거절하거나 조작이 안 됨), 우리가 만든 페이지를 사진 한 장으로 확인하는 것처럼 창이 필요 없을 때, 같은 확인을 수십 번 되풀이할 때(창이 앞 화면을 계속 빼앗는다).
- **바꾸지 않는 때**: 캡차·403·봇 차단·robots·약관 금지로 막힌 것은 헤드리스로 바꿔 넘지 않는다 — 그것은 우회다. 1절 판정대로 멈추고 사용자에게 알린다. 대량 수집은 어느 브라우저로도 하지 않는다.

- 정체: [Aside](https://aside.com) — 에이전트가 든 macOS 브라우저(15.0+). CLI 가 그 브라우저를 조작한다. **보이는 창이고 사용자의 로그인·쿠키를 쓴다** → 사용자 계정으로 하는 일이 된다. 사용자가 보이는 창을 꺼리는 프로젝트(메모리·CLAUDE.md)면 그 규칙이 먼저다.
- 설치: CLI `curl -fsSL https://releases.aside.com/install.sh | bash`(받아서 먼저 읽고 실행 — `~/.aside/cli` 에 풀고 `~/.local/bin/aside` 를 만든다. 그 폴더가 PATH 에 없으면 넣는다) + 앱 `brew install --cask aside`. 앱을 열고 로그인하는 것은 **사용자**(`aside login` → 앱 Settings > Account > Devices 에서 승인). 앱이 꺼져 있으면 CLI 가 "Aside isn't running" 을 낸다 → 사용자에게 앱을 켜 달라고 한다.
- 쓰기 전에 `aside guide`, `aside guide repl` 을 읽는다(판마다 바뀐다). 맞는 사이트 스킬이 있으면 `aside skills list` → `aside skills show <이름>` 을 먼저.
- `aside exec "<할 일>"` — Aside 의 에이전트에게 맡긴다(하위 에이전트처럼). 결과만 필요할 때.
- `aside repl "<JS>"` — Playwright 식 JS 로 직접 조작(120초 한도, `const` 가 이어지니 새 이름을 쓴다, `console.log` 로 값을 돌려받음). 사용자가 연 탭은 `listBrowserTabs()` → `attachBrowserTab(id)`/`attachActiveBrowserTab()`, 새 페이지는 `openTab(url)`, 읽기는 `snapshot(page, { interactive: true })`, 확인은 `page.screenshot()`. 사용자가 연 탭에 붙는 것이 2절 ②(사용자가 연 페이지 읽기)와 같은 범위다.
- `aside memory` 는 사용자의 개인 맥락이다 — 필요한 것만 읽고 저장소에 옮겨 적지 않는다. 결제·보내기·삭제처럼 되돌리기 어려운 클릭은 하기 전에 사용자에게 확인한다.

## 3-3. 실행 파일 역공학을 서브에이전트에 맡길 때 (게임 클라이언트처럼 큰 대상)

메이플(2026-10-17~21)에서 판마다 통한 방식:
- **질문 목록을 우선순위대로** 준다(「1. 무기 계열마다 어느 숙련 스킬을 보나 2. 공격 속도 셋째 인자는 어디서 오나 …, 시간이 모자라면 아래는 미확인」). 「스킬을 분석해」처럼 넓게 주면 끝이 없다.
- 지금까지 확인한 것(분석서 절·주소·표기법)을 먼저 읽게 하고 **다시 하지 말라**고 적는다. 커뮤니티 IDB 이름표(같은 해시면)·이전 판의 헤드리스 디컴파일 덤프·objdump 전체 풀이를 스크래치에 두고 재사용하게 한다 — 한 판 15분 안팎.
- 돌려받는 꼴을 정한다: 항목마다 **[관찰]/[추정]/미확인 + 근거 주소**(함수·asm·증거 ID) 표, 마지막에 「메인이 그대로 옮길 규칙」 목록. 프로젝트 파일은 쓰지 말고 텍스트로 — 문서 반영은 메인이 한다(번호 충돌·문체).
- 소스가 있는 에뮬레이터도 참고로 읽게 하되 **근거는 클라이언트 코드**, 다르면 둘 다 적게 한다.
- 돌아오는 동안 메인은 겹치지 않는 일(에뮬레이터에 명세가 있는 부분)을 먼저 만든다. 질문을 더할 일이 생기면 실행 중인 에이전트에 메시지로 덧붙인다.
- 받은 결과 중 **분기·개수처럼 틀리면 동작이 바뀌는 것**은 메인이 디스어셈블로 한 번 더 읽는다(「정확히 1마리」 → 실제 「하나라도」였던 사례).
- 분석서에 옮길 때 절 번호가 이미 쓰였는지 목차를 grep한다.

## 4. 만든 뒤

- 사이트 구조가 바뀌면 파서가 조용히 틀린다 → 필수 필드가 비면 저장하지 않고 "읽기 실패"로 표시하는 테스트를 하나 둔다.
- 존재 확인(매물이 아직 있나)은 1절 판정이 **허용**일 때만 자동으로, 그 외에는 사용자가 그 매물을 다시 열 때 ②로 갱신한다. 마지막 확인 시각을 항상 같이 보여 준다.
