# 남의 앱·웹 동작 파악 (역공학) — EXPLORE 보조

> 연동·재현하려는 기능이 **남의 앱·웹사이트 안**에 있을 때 읽는다(예: 부동산 포털 매물 페이지에서 매물 ID·가격·등록일이 어디서 오나).
> 도구: [morluto/rea](https://github.com/morluto/rea) — "Reverse Engineer Anything" MCP(MIT, ★20.8만, 2026-10-14 확인). 웹사이트(페이지 구조·스크립트·네트워크 관찰), 저장한 HAR, Android APK·기기, JS/Electron, .NET, 네이티브 바이너리를 **증거와 한계를 붙여** 돌려준다.
> 순서: **관문 → 가장 덜 침습적인 방법 → 필요할 때만 REA**. 관문을 건너뛰면 기능을 다 만든 뒤 법·차단 때문에 버리게 된다.

## 1. 관문 (코드 전에, SPEC "안 할 것·제약"에 기록)

대상마다 아래를 확인하고 출처 URL·확인일을 남긴다.

| 확인 | 어떻게 |
|---|---|
| robots.txt | `curl -s -A "Mozilla/5.0" https://<호스트>/robots.txt` — 호스트마다 다르다(같은 회사도 서브도메인별로 다름) |
| 이용약관의 자동 수집·복제 조항 | 서비스 약관 원문. 못 찾으면 "미확인"으로 두고 허용으로 치지 않는다 |
| 봇 차단 | 평범한 요청에 403·캡차·CloudFront/Akamai 차단 페이지가 오면 **차단된 것** |
| 로그인·유료 필요 여부, 개인정보(중개사 연락처 등) 포함 여부 | 페이지를 사람이 열어 본다 |

판정:
- **허용**(robots 허용 + 약관에 금지 없음): 공개 페이지를 낮은 빈도로, 사용자가 고른 건만 읽는다.
- **애매**(약관 미확인·robots 일부 금지): **사용자 주도 방식만** — 아래 2절 ①②.
- **금지·차단**(robots 전면 금지, 약관 금지, 봇 차단): 자동 수집하지 않는다. 사용자가 화면에서 본 값을 입력·교차검증용으로만 쓴다.

어떤 경우에도 하지 않는다: 봇 차단·캡차·로그인·DRM·접근 통제 우회, 대량·체계적 수집(저작권법 DB 제작자 권리, 정보통신망법·업무방해 위험), 비공개 API를 반복 호출해 그 서비스를 대신하는 것. REA 자체 고지(DISCLAIMER.md)도 같은 선을 긋는다.

## 2. 덜 침습적인 방법부터

① **공유 URL 파싱** — 사용자가 앱·웹의 공유 버튼으로 받은 URL에서 사이트·매물 ID를 뽑는다. 네트워크 요청 0회. 출처 기록·중복 판별은 이것만으로 된다.
② **사용자가 연 페이지 읽기** — 북마클릿·브라우저 확장이 **사용자 브라우저에서 사용자가 지금 보고 있는 페이지 1건**의 DOM(또는 페이지에 이미 실린 JSON)을 읽어 우리 앱에 보낸다. 사람이 연 화면을 옮겨 적는 것과 같은 범위. (예: bergside/design-md-chrome이 같은 방식으로 스타일을 읽는다.)
③ **공식 API·제휴·공개 데이터**가 있으면 그것이 우선이다(국토부 실거래처럼).
④ 위로 안 될 때만 REA로 구조를 파악한다(3절). 파악 결과로 ①②의 파서를 만드는 데 쓰고, 자동 반복 수집으로 바로 가지 않는다.

## 3. REA로 파악하기

- 설치는 사용자가 직접(대화형 승인): `! npx rea-agents setup` → 에이전트 재시작. Node 22.19+ 필요. 설치돼 있지 않으면 브라우저 도구(개발자 도구 네트워크 탭)로 같은 관찰을 한다.
- 웹: 사용자가 **자기 브라우저에서 평소처럼 연 페이지**를 브라우저 분석하거나, 사용자가 저장한 HAR을 넘겨받는다. HAR은 쿠키·인증 헤더를 지운 뒤 받는다(`docs/web-network-captures.md`).
- 앱: APK 정적 분석(JADX)은 "어떤 화면이 어떤 데이터를 쓰나"를 아는 데까지만. 인증서 고정 해제·트래픽 가로채기는 1절 금지 항목에 걸리면 하지 않는다.
- 결과는 REA 형식 그대로 **증거·한계**를 붙여 SPEC에 남긴다: 필드 대응표(사이트 필드 → 우리 필드), 식별자(매물 ID·URL 패턴), 변경·삭제를 알 수 있는 신호, 그 신호가 틀릴 수 있는 경우.

## 4. 만든 뒤

- 사이트 구조가 바뀌면 파서가 조용히 틀린다 → 필수 필드가 비면 저장하지 않고 "읽기 실패"로 표시하는 테스트를 하나 둔다.
- 존재 확인(매물이 아직 있나)은 1절 판정이 **허용**일 때만 자동으로, 그 외에는 사용자가 그 매물을 다시 열 때 ②로 갱신한다. 마지막 확인 시각을 항상 같이 보여 준다.
