# 차트 고르기·구성 (Charts — type selection & composition)

> 범례·축·주석·툴팁의 세부는 `legend-annotation.md`, 스파크라인·KPI는 `kpi-dashboard.md`, 폰 차트 높이·터치 툴팁은 `mobile-adaptation.md`.
> 이 파일은 그 앞 단계 — **어떤 차트를 쓰나, 한 차트에 무엇을 얼마나 겹치나, 점이 적거나 빈 구간은 어떻게 하나**를 정한다.
> 실제 사용자 지적(2026-10-14 부동산 판정 앱): "시세 추이 차트부터 엉망" — 분기 중앙가 선과 거래 건수 막대가 같은 무게로 겹치고, 점이 드문 구간이 추세처럼 보였다.
> 이 환경에 `dataviz` 스킬이 있으면 색·마크 규격은 그 스킬을 먼저 읽고, 이 파일은 구조 결정에 쓴다.

## 1. 차트 종류 고르기

- 시간에 따른 변화 = 선. 범주 비교 = 막대. 값 vs 기준 = 불릿(`verdict-score-report.md` §3). 구성비 = 100% 누적 막대(파이는 조각 5개 이하일 때만, `legend-annotation.md`) [S1 row 1·2·18].
- 시계열 점이 **4개 미만**이면 차트를 그리지 않고 값 + 델타 텍스트로 쓴다 [S1 row 1]. (스파크라인의 "2개 이하" 규칙보다 엄격 — 축이 있는 차트는 4개부터.)
- 계열(선)은 **5개 이하**. 6개 이상이면 작은 배수(small multiples)나 표 [S1 row 1].
- 범주 막대는 **값 내림차순** 정렬(순서가 의미인 범주 — 시간·등급 — 는 예외). 범주 **15개 초과면 표**, 20개 이상이면 가로 막대 [S1 row 2].
- 분포(상자·산점)는 그룹당 표본 **20개 미만이면 그리지 않는다** — 점을 그대로 찍거나 표 [S1 row 4·17].
- 지역 면적 차이가 큰 지도 단계구분도(choropleth)는 면적이 값처럼 보인다 → 정렬 막대를 함께 둔다 [S1 row 6].

## 2. 한 차트에 두 가지를 겹칠 때 (가격 선 + 거래량 막대)

- 주인공 하나만 위 영역을 쓴다: **가격 선(2px 실선)이 위 70~75%**, **건수 막대는 아래 25~30%에 낮은 채도·불투명도 40%** [S1 row 15, 비율은 권장(근거 약함)].
- 두 값의 축은 섞지 않는다: 왼쪽 = 가격(단위 `만원/㎡`), 오른쪽 또는 막대 영역 안쪽 = 건수. 오른쪽 축의 눈금선은 그리지 않는다(격자가 두 벌이 된다). 이중축 일반 규칙은 `legend-annotation.md` §2.
- 겹치기 싫으면 **위아래 두 패널로 나누고 x축을 공유**한다(가격 패널 높이 : 건수 패널 = 3 : 1). 같은 x축이면 이쪽이 읽기 쉽다 — 겹칠지 나눌지는 폭이 좁은 폰에서는 나누는 쪽을 기본으로 한다(권장).
- 막대와 선이 같은 색 계열이면 선을 진하게(잉크/주색), 막대를 옅게(같은 색 20~40%) — 다른 색 두 개를 같은 채도로 쓰지 않는다.

## 3. 점이 드물거나 빈 구간

- 표본이 기준 미만인 구간(예: 분기 거래 2건 미만)은 **선을 잇지 않고 끊는다**. 그 구간은 점만 찍거나 비우고, 축 아래에 `거래 적음` 같은 작은 표시를 둔다 — 이어 그린 선은 없는 추세를 만든다.
- 진행 중인(아직 덜 찬) 기간은 실선으로 잇지 않는다: 점선 또는 빈 원 마커 + "진행 중" 라벨.
- 실측 = 실선, 추정·예측 = 점선, 범위(신뢰구간·최저~최고) = 15% 채움 [S1 row 1·9]. 색만으로 구분하지 않는다(WCAG 1.4.1).
- 계열·기준선에는 **직접 라벨**(선 끝에 이름·마지막 값). 범례 박스는 계열이 3개 이상일 때만(`legend-annotation.md` §1).

## 4. 숫자와 축

- 축 숫자·툴팁 숫자는 `font-variant-numeric: tabular-nums`. 단위는 축 제목에 한 번만 쓰고 눈금에는 반복하지 않는다(`legend-annotation.md` §2).
- 큰 수는 축약(`549만`, `12억`). 소수 자리는 차트 전체에서 하나로.
- y축을 0에서 시작하지 않는 선 차트는 축 시작값을 눈금에 보이게 둔다. 막대는 항상 0에서 시작한다(길이가 값이므로).

## 5. 크기·상태·대체

- 차트 영역 높이는 데이터가 오기 전부터 **고정(예약)** 한다 — 늦게 그려지며 아래를 밀면 화면이 흔들린다 [S2 #19]. 로딩은 같은 높이의 스켈레톤.
- 모든 차트에 같은 값을 담은 **표 보기(기본 접힘)** 또는 한 줄 요약을 둔다. 호버로만 보이는 값이 없게 한다 — 터치·키보드에서 못 읽는다 [S1 A11y Fallback].
- 차트 위 제목은 결론형 한 줄("3년간 ㎡당 549만→692만, 거래는 줄어듦")이 라벨형("시세 추이")보다 낫다 — 결론 없는 차트는 해석을 사용자에게 떠넘긴다(`verdict-score-report.md` §1).
- 렌더링: 점 1,000개 미만 SVG, 그 이상 Canvas + 다운샘플링 [S1 row 1].

## Do / Don't

- Do: 주인공 계열 1개를 진하게, 나머지는 옅게. 빈 구간은 끊고 표시. 결론형 제목. 표 보기 접힘.
- Don't: 선과 막대를 같은 높이·같은 채도로 겹치기. 점 3개로 축 있는 선 차트. 거래 1건짜리 분기를 이어 추세처럼 보이기. 격자 두 벌. 범례 박스 + 직접 라벨 중복. 장식 그라디언트 채움.

## 체크

- [ ] 점 4개 미만이면 숫자로 대신했나? 계열 5개 이하인가?
- [ ] 겹친 차트에서 주인공이 위 영역을 쓰고 보조는 아래 25~30%·옅은가(또는 x축 공유 두 패널)?
- [ ] 표본 부족·진행 중 구간을 끊거나 점선으로 구분했나?
- [ ] 높이 예약·스켈레톤, 표 보기 접힘, 결론형 제목이 있나?
